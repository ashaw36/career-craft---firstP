## 二、角色档案系统设计

### 核心机制：经历-角色适配度评分（Fit Score）

```
统一经历库 (Experience Pool)
    │
    ├── 经历A: 搭建推荐系统，QPS 10万 → 技术标签 [后端, 高并发]
    ├── 经历B: 主导用户增长，DAU从10万→100万 → 标签 [增长, 数据分析]
    └── 经历C: 设计对话机器人交互流程 → 标签 [AI产品, UX设计]

角色档案 (Persona Profile)
    │
    ├── 能力侧重向量: {产品规划:0.9, 技术实现:0.6, 商业分析:0.7}
    └── 目标岗位画像向量: {AI产品:1.0, 用户增长:0.4, 后端开发:0.2}

适配度计算:
    FitScore = Σ(经历标签权重 × 角色能力侧重 × 目标岗位相关性)
```

### 提取与组装流程

1. **过滤（Filter）**：剔除与角色定位明显冲突的经历
2. **排序（Rank）**：按 Fit Score 降序排列
3. **重述（Reframe）**：同一份经历，根据角色侧重调整描述角度
4. **裁剪（Trim）**：控制简历篇幅，保留 Top N 经历
5. **补充（Augment）**：根据角色能力模型，标注隐含能力

### 不同角色的差异化策略

| 维度 | AI PM 角色 | 销售角色 | 架构师角色 |
|------|-----------|---------|-----------|
| 经历筛选 | 产品规划、跨部门协作、数据决策 | 客户成功案例、商务谈判、业绩数据 | 系统设计、技术深度、复杂问题解决 |
| JD匹配重点 | 产品方法论、AI技术理解、用户洞察 | 行业资源、成单率、客户维护 | 系统规模、技术选型、架构演进 |
| Gap分析方向 | LLM产品实践、Prompt Engineering | 销售方法论（SPIN/MEDDIC） | 云原生/分布式特定技术栈 |

## 三、核心数据模型

### 实体关系概览

```
User ──1:N──▶ Persona ──1:N──▶ RoleExperienceWeight
                ──1:N──▶ PersonaCapability
                ──N:M──▶ Experience
                ──1:N──▶ JobMatch ◀──1:N── JobDesc
                ──1:N──▶ LearningPath ──1:N──▶ LearningItem

Experience ──N:M──▶ SkillNode
SkillNode ──自关联── parent_id
```

### 关键实体字段

**Experience**
- id, user_id, type(work/project/education/cert), title, organization
- start_date, end_date, raw_description, structured_achievements[], skills_demonstrated[]
- metrics[], artifacts[]

**Persona**
- id, user_id, name, is_default, identity_statement, career_narrative, tone_style
- capability_weights, target_job_profiles, max_experiences, preferred_model

**RoleExperienceWeight**
- id, persona_id, experience_id, relevance_score, reframed_summary, highlighted_skills[]
- user_overridden

**SkillNode**
- id, name, category, description, parent_id, aliases[], vector_embedding

## 五、关键边界情况

| 场景 | 问题 | 应对策略 |
|------|------|---------|
| 经历真空 | 应届生/转行者经历库毒乏 | 允许录入课程项目/个人作品；角色标记"成长型"；强化学习路径 |
| 模型幻觉 | LLM错误解析经历 | 所有AI提取内容必须用户确认；保留原始描述作为 Source of Truth |
| 过度拟合 | 用户追求高匹配度让AI编造 | 区分"润色表达"与"虚构内容"；添加真实性确认步骤 |
| 多角色膨胀 | 10+角色导致数据膨胀c | 限制角色数量；建立"重述版本"继承机制；全局同步更新工具 |
| 隐私敏感 | 经历包含前公司机密 | 本地优先架构；脱敏提示；支持本地LLM |
| 目标岗位漂移 | 频繁修改目标岗位 | 保存"岗位意图历史"；允许"探索模式"（不写入正式档案） |
| 空白期矛盾 | 时间重叠、空白期未解释 | 时间线冲突自动检测；空白期引导用户补充说明 |
